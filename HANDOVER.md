# Handover

An online store for a Swiss Korean-skincare (K-beauty) shop.
- Shop in German, French, Italian and English, prices in CHF.
- Admin where the client manages products, stock, orders and the homepage.
- Built as a demo for the client and not live yet.

## Start here

1. Set up and run it locally: [docs/DEPLOY.md](docs/DEPLOY.md), "Local development". It takes about 10 minutes, and `npm run db:restore` gives you the same catalogue as the demo.
2. Open `http://localhost:3000/admin`. The restored database has no user accounts, so the first account you create becomes the admin.
3. Read:
   - [PRODUCT.md](PRODUCT.md): what the store is for, who uses it, and the rules for claims and placeholder content.
   - [DESIGN.md](DESIGN.md): colours, type and components. Light pink, white and black, Google Sans.
   - [docs/STORE-GUIDE.md](docs/STORE-GUIDE.md): the guide for the client on using the admin.

## Stack

- **Framework:** Next.js 16 (App Router) and Payload CMS 3 in one app. The admin is at `/admin`.
- **Database:** Postgres. During development, Payload changes the tables to match the code. In production it runs the files in `src/migrations`.
- **Shop logic:** `@payloadcms/plugin-ecommerce` handles products, variants, carts, orders and Stripe payments (TWINT, cards, Apple Pay, Google Pay).
- **Photos:** stored on disk in `media/` when no Cloudinary keys are set (local), and on Cloudinary in production.
- **Languages:**
  - Interface text is in `src/i18n/messages/`.
  - Admin content uses Payload localization.
  - The chosen language is kept in a `lang` cookie.
- **Next.js version:** `AGENTS.md` notes that this Next.js has breaking changes. Check `node_modules/next/dist/docs/` before relying on older Next.js knowledge.

## Where things are

| Path | What |
|---|---|
| `src/app/(frontend)` | Shop pages: home, shop, product, checkout, account |
| `src/app/(payload)` | Admin and API routes, generated by Payload. Don't edit by hand. |
| `src/collections`, `src/globals` | Data models: products, categories, media, users, homepage |
| `src/payload.config.ts` | Payload setup: database, languages, shop plugin, payments, email, storage |
| `src/components` | Shop components |
| `src/i18n` | Translations and language switching |
| `src/seed/real-products*.ts` | Import of the client's real range from the posters in `Products/` (`npm run import:products`) |
| `src/seed/index.ts` | Older placeholder catalogue (`npm run seed`) |
| `scripts/` | Local database (`db:*`) and a temporary public demo link (`npm run share`) |
| `handover/database.sql` | Database snapshot: products, categories, photo records, homepage. No users, carts or orders. |

## Current state

Works end to end locally:
- shop, search and categories;
- product pages, bag and checkout;
- customer accounts and order history;
- admin, stock;
- language switching.

The catalogue holds the client's 45 real products, imported from their posters.

## Still to do

1. **Real prices and stock.** All prices and stock levels (20 each) are placeholders. Get the client's price list, then update the products in the admin or in `src/seed/real-products.data.ts`. If you re-run `import:products`, note that it wipes all products and photos first.
2. **Check the product texts against the posters.** The two routine sets mention an SPF 50+ sun cream and a "brightening peeling gel" that weren't fully identified.
3. **Keys and accounts:** Stripe (test, then live), Cloudinary and SMTP email. They go in `.env` locally and in Render's settings in production. Without Stripe keys, checkout cannot take payment.
4. **Deploy to Render** with `render.yaml`, following [docs/DEPLOY.md](docs/DEPLOY.md). The local `media/` photos must be uploaded to Cloudinary, or the products re-imported against the production database with the Cloudinary keys set.
5. **Brand name and content.** "Your Brand" is a placeholder (`NEXT_PUBLIC_BRAND_NAME`). The homepage reviews, ingredient cards and brand story are sample text in `src/data/sample-content.ts`, and must be replaced or removed before launch.
6. **Legal pages:** imprint (Impressum), privacy policy, terms and returns.
7. **Not built yet:** shipping rates, translated emails, newsletter connection, a reviews system. See "Known limits" in [docs/DEPLOY.md](docs/DEPLOY.md).

## Notes

- **Image licences:** the hero photo, ingredients background and story portrait came from the previous developer. Their licences are unconfirmed, so check them before launch.
- **Repository visibility:** it contains the client's product posters (`Products/`) and photos (`media/`). Make it private if the client prefers.
- **Admin access:** the first admin account is created at `/admin`. Shoppers who sign up through the shop are customers and cannot open the admin. The access rules are in `src/access/index.ts`.
